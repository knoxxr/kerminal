# 수동 검증 체크리스트

CI는 컴파일과 단위 테스트만 확인합니다. 아래 항목은 **실제 기기·실제 서버에서만**
확인되는 것들로, 위험한 순서(실패 시 피해가 큰 것 먼저)로 정렬했습니다.

각 항목은 **무엇을 하고 → 무엇이 나와야 통과인지**로 적었습니다. 실패하면 "실패 시
알려줄 것" 항목을 그대로 전달하면 원인 파악이 빨라집니다.

준비물: SSH 접속 가능한 서버 1대(테스트용 계정), 안드로이드 기기, Windows PC,
macOS. 서버가 없으면 `ssh localhost`가 가능한 macOS/Linux 자체를 대상으로 써도
대부분 확인됩니다.

---

## A. macOS 자격증명 저장소 — 최우선

가장 위험합니다. 실패하면 **저장된 비밀번호와 SSH 키를 잃습니다**. 볼트 코드를 전부
다시 썼고(초기화 단일화, 원본 보존, 권한 600) CI는 컴파일만 확인했습니다.

> 먼저 기존 볼트를 백업하세요:
> `cp -a ~/Library/Application\ Support/kr.minary.kerminal ~/Desktop/kerminal-vault-backup`

1. 서버를 하나 추가하고 **비밀번호를 입력해** 저장 → 접속되는지
2. **앱을 완전히 종료하고 다시 실행** → 같은 서버에 **비밀번호를 다시 묻지 않고** 접속
   - ❌ 비밀번호가 빈 채로 접속 실패하면 → 볼트 읽기 실패
3. 서버 2개를 **연달아 빠르게** 추가 (초기화 경쟁 조건 확인)
   - ❌ `LateInitializationError` 크래시 → 잠금 실패
4. 볼트 권한 확인:
   `ls -l ~/Library/Application\ Support/kr.minary.kerminal/vault.*`
   - ✅ `-rw-------` (600)
5. 손상 복구: 앱 종료 → `vault.enc`를 아무 텍스트로 덮어쓰기 → 앱 실행
   - ✅ `vault.enc.unreadable` 파일이 **생겨 있고**(원본 보존), 앱은 정상 실행
   - ❌ 원본이 그냥 사라지면 → 보존 로직 실패

**실패 시 알려줄 것**: 3~5번 중 어디서, 크래시면 화면 메시지, 5번이면 그 폴더의
`ls -la` 결과.

## B. 안드로이드 세션 유지

원래 요청이었고 아직 확인되지 않았습니다.

1. 서버 접속 → 알림창에 **"Keeping 1 session connected"** 표시
   - 안드로이드 13+는 알림 권한을 한 번 물음 → 허용
   - ❌ 알림이 없으면 → 포그라운드 서비스 시작 실패
2. 터미널에서 `watch -n1 date` 실행 (없으면 `while true; do date; sleep 1; done`)
3. **홈 버튼으로 다른 앱으로 전환 → 1분 이상 대기 → Kerminal 복귀**
4. 판정:
   - ✅ **시계가 끊김 없이 계속 돌고 있다** → 세션 유지 성공
   - ⚠️ `[Link dropped while in background]` / `[Reconnecting…]` 이 찍혔다 →
     소켓이 죽어 재연결된 것 (유지 실패, 재연결은 동작)
   - ❌ **탭이 아예 사라졌다** → 안드로이드가 액티비티를 파괴한 것
     (Flutter 엔진 캐싱이 필요 — 후속 작업)
5. 마지막 탭 닫기 → 알림 사라짐 / 앱을 스와이프로 종료 → 알림 사라짐

> 삼성·샤오미 등은 **설정 → 배터리 → 앱 배터리 관리에서 Kerminal을 "제한 없음"**
> 으로 두세요. 제조사 최적화가 포그라운드 서비스까지 죽이면 4번이 실패합니다.

**실패 시 알려줄 것**: 4번의 세 갈래 중 어느 것인지, 기기 제조사·안드로이드 버전,
배터리 최적화 설정 상태.

## C. 탭 전환 (모바일)

1. 서버 3개 이상 접속 → 앱바 아래 **탭 줄이 전체 폭으로** 보이는지
2. 탭 줄을 **좌우로 스와이프** → 스크롤되는지 (드래그 재정렬에 막히지 않아야 함)
3. 탭을 **탭** → 전환되고, 선택된 탭이 화면 안으로 자동 스크롤되는지
4. 제목(또는 탭 아이콘)을 탭 → **세션 목록 시트**가 열리고 거기서 전환·닫기 되는지
5. 탭을 **길게 눌러** 드래그 → 순서가 바뀌는지

---

## D. SFTP 파일 전송

1. 접속된 터미널 상단 **폴더 아이콘** → 파일 목록이 뜨는지
   - ✅ 홈 디렉터리 내용이 보임 (경로 표시줄에 "Home")
   - ❌ 오류 배너 → 메시지 내용 필요
2. 폴더를 탭해 이동 → **경로 표시줄의 중간 단계**를 탭해 되돌아오기 → ↑ 버튼
3. **작은 텍스트 파일을 탭** → 다운로드
   - 데스크톱: 저장 위치 선택 창 → 저장 후 파일 내용이 맞는지
   - 안드로이드: "Saved to /…" 경로 안내 → 그 경로에 파일이 있는지
4. **⬆ 버튼으로 업로드** → 서버에서 `ls -l` 로 크기가 일치하는지 확인
   (중요: 내용이 깨지지 않았는지 `md5sum` 비교 권장)
5. 새 폴더 만들기 → 이름 바꾸기 → 삭제
6. **비어 있지 않은 폴더 삭제 시도** → "빈 폴더만 삭제 가능" 안내대로 실패하는지
7. **한글 파일명**이 있는 디렉터리 → 이름이 깨지지 않는지

**실패 시 알려줄 것**: 어느 단계, 오류 배너 문구 전체, 서버 OS(Linux/BSD 등).

## E. 2단계 인증 (OTP)

OTP를 요구하는 서버가 필요합니다. 없으면 이 항목은 건너뛰되 **미검증으로 남깁니다**.

1. 해당 서버에 접속 → **서버가 보낸 프롬프트 그대로** 입력창이 뜨는지
2. 코드 입력 → 접속 성공
3. 코드 입력창에서 **취소** → 접속이 실패로 끝나는지(빈 코드가 전송되지 않아야 함)
4. 그 세션에서 **Reconnect** → 다시 코드를 물어보는지
5. **SFTP 열기** → **코드를 다시 묻지 않아야 함** (인증된 연결 재사용)

## F. `~/.ssh/config` 가져오기 (데스크톱)

1. 서버 목록 ⋮ → **Import from ~/.ssh/config**
2. 목록에 실제 항목들이 뜨는지, **`Host *` 같은 패턴이 빠져 있는지**
3. 이미 저장된 서버가 **기본 해제** 상태인지
4. `ProxyJump`가 있는 항목에 **"needs jump host … not supported yet"** 표시
5. 가져오기 → `Imported` 그룹에 들어가고, **비밀번호/키는 비어 있는지**
6. 같은 작업을 **한 번 더** 실행 → 중복이 생기지 않는지

---

## G. 터미널 색 테마

1. 설정 → Terminal → 6개 테마가 **각자의 색으로 렌더**되어 보이는지
2. 하나 선택 → 열려 있는 터미널 색이 바뀌는지
3. **앱 재시작** → 선택이 유지되는지
4. 글꼴 크기를 바꾸면 미리보기에도 반영되는지
5. 터미널 상단 여백이 **배경과 같은 색**인지(다른 색 띠가 보이면 실패)

## H. 문의 기능

1. 설정 → Support → Contact us → 메시지 입력 → Send
2. ✅ **"Thanks — your message was sent."** → 메일함(스팸함 포함) 확인
3. ⚠️ "received, but email delivery is currently failing" → 저장은 성공,
   Resend 발신 주소 문제 (`supabase/README.md` §5 참고)
4. ❌ 그 외 오류 → Edge Functions 로그의 해당 줄 필요

## I. 동기화 (계정 사용 시)

1. 두 기기에서 같은 계정으로 로그인·잠금 해제 → 한쪽에서 서버 추가 → 다른 쪽에 나타나는지
2. 동료 이메일로 공유 초대 → **대문자가 섞인 주소로 가입한 계정도 검색되는지**
   (이번에 고친 항목 — `schema.sql` 재실행이 되어 있어야 합니다)
3. 목록 상단에 **동기화 경고 배너가 뜨지 않는지**(뜨면 그 문구 필요)
4. 호스트 편집 → 변경 이력에서 이전 버전으로 **되돌리기**가 동작하는지

## 결과 정리

통과/실패만 알려주셔도 됩니다. 실패한 항목은 위의 "실패 시 알려줄 것"을 함께 주시면
원인을 좁혀 바로 수정하겠습니다. **A와 B가 가장 중요합니다** — A는 데이터를 잃는
경로, B는 원래 해결하려던 문제입니다.
